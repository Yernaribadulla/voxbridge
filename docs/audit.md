# Проверка VoxBridge 0.4.0

Дата: 16 октября 2026. База: `main`, `550fc4c`.

## Исправленные проблемы

| Область | Проблема | Изменение |
| --- | --- | --- |
| Mouse 5 | Callback принимал два аргумента вместо `x, y, button, pressed` и завершал listener с TypeError | Правильная сигнатура, поддержка дополнительного флага injected, защита от повторного press |
| Hook lifecycle | Сбой keyboard hotkeys оставлял mouse listener активным | Откат обоих listeners; stop освобождает удерживаемую кнопку |
| Очередь распознавания | При переполнении микрофон удалял самый приоритетный элемент через PriorityQueue.get | Две FIFO с общей границей; partner никогда не вытесняет микрофон |
| Перевод | ThreadPoolExecutor ограничивал workers, но не число ожидающих задач | Отдельная ограниченная очередь на 8 заданий и два workers |
| Capture | Поколение partner-фрагмента определялось при flush, что могло приписать старый звук новому маршруту | Проверка маршрута до/после read и сохранение поколения самого буфера |
| Отпускание PTT | Последний read микрофона мог теряться после перехода в FINALIZING | Сохранение последнего стабильного read, начатого при удержании |
| Qt delivery | Уже поставленный в GUI результат мог пережить PTT или смену настроек | Повторная проверка engine ID, generation и sequence при доставке |
| Смена настроек | Новый счётчик sequence начинался с нуля, но UI помнил номер прежнего движка | Новый ResultGate для каждого движка |
| Модель / завершение | Старые background jobs и экземпляры движка не имели ясного завершения | Закрытие очередей, stop capture, кооперативное ожидание и освобождение retired-модели |
| Capture failure | После ошибки устройство могло оставаться «активным» без рабочего потока | Пауза с ошибкой и пересоздание capture по явному resume |
| Настройки | Нет проверки полей; запись неатомарная; часть параметров UI игнорировалась | Нормализация отдельных полей, temp + fsync + replace, рабочие font/opacity controls |
| HTTP | Ошибки структуры/JSON, proxy и redirects не контролировались | Проверка endpoint, ограничение ответа, явные ошибки, отключённые proxy/redirect |
| Сборка | Spec использовал относительный путь `../app`, неверный при запуске из корня | Пути от SPECPATH, QSS и данные пакетов включены в описание сборки |
| Документация | Привязка к частному локальному пути, недостаточно сведений о режимах/ограничениях | README, архитектура, changelog, инструкции разработки и CI |

## Архитектурное решение

Это небольшое модульное настольное приложение. Микросервисы для передачи аудио между capture, Whisper и UI не добавлены: очереди передают PCM в памяти и позволяют использовать одну модель. LM Studio уже отдельный сервис. Приоритет, очереди и допустимость результатов вынесены в независимые от UI модули `app/core`.

## Выполненные проверки

- Исходный набор: **6 тестов**.
- Итоговый набор: **57 тестов**, без реального звука, model weights, LM Studio и глобальных hooks. В том числе реальные Python workers с fake capture/recognizer/translator, конкурирующие PTT-запросы и смена поколения во время заблокированного распознавания.
- `python -m compileall -q app tests` — успешно.
- `ruff check app tests --select E9,F` — успешно; исходники отформатированы.
- Wheel `voxbridge-0.4.0-py3-none-any.whl` собирается через `pip wheel --no-deps --no-build-isolation`.
- Содержимое wheel проверено: код приложения, QSS и console entry point включены.
- `git diff --check` — успешно.
- CI настроен на Windows / Python 3.11 и 3.14, Ubuntu / Python 3.11, с тестами и сборкой wheel.

## Границы проверки

Реальные аудиоустройства не открывались, Whisper-веса не загружались, запросы перевода к реальному серверу не отправлялись. После ограничения на запуск приложения выполнялись только проверки исходников, component tests без окон и сборка Python-пакета. Полная визуальная проверка обновлённого интерфейса, реальный WASAPI/CUDA, глобальные hooks в игре и запуск собранного EXE не выполнялись.

PyInstaller-spec исправлен, но полный Windows executable в этой проверке не собирался. Wheel не содержит сторонние зависимости и не является автономным EXE.

Остаются ограничения native inference и драйверов: уже начатый вызов нельзя безопасно прервать из Python; при перегрузке ограниченные очереди могут пропускать старые фрагменты. Внешний endpoint получает текст явно; приложение не предоставляет TTS/виртуальный микрофон или гарантию отображения над exclusive fullscreen.
